# 微信采集首次启动卡住

2026-10-13 通过真实 GUI 冷启动复现：点击开启采集后，按钮变为暂停采集，但状态一直停留在“正在读取微信窗口”。

阶段日志和 Python 阻塞栈显示：额外启动的采集子进程卡在 NumPy 原生模块导入，尚未进入微信窗口查找。改用 pythonw 后导入恢复，但跨进程同步锁继续报 PermissionError；服务端队列读取也受影响，界面未能正确收到采集错误。

最终改为 Go/Wails 界面 → Python 服务进程 → 后台采集线程。界面仍与采集分进程隔离；NumPy 在服务启动时加载，OCR 在后台线程预热。启停使用 threading.Event 和 queue.Queue，不再传递跨进程同步锁。暂停保留引擎，退出唤醒线程并释放 WGC；每个采集线程拥有独立退出事件。

真实 GUI 首次点击到收到消息约 1.52 秒，其中窗口查找约 6 毫秒，证据不支持把此次卡住归因于窗口枚举速度。保留原有按进程和主窗口标题定位 HWND 的方案，以及首帧超时重连。

需要排查时，可设置环境变量 JUNSHI_CAPTURE_TRACE 为日志文件路径，再启动程序。日志只记录阶段、PID 和时间，不记录会话名称、消息文本或截图；默认关闭。
